# 自分の表示名の変更

Issue #44。ログイン済みユーザーが自分を識別できる表示名へ変更する。新規ユーザー作成・他人のプロフィール編集は対象外。

## 受け入れ条件

- `/workspaces` の「ログイン状況」に表示名フォームを置く。ログイン済みならロールや所属先の有無を問わず利用できる。
- 前後の空白をJavaScript `trim` と同じ規則で除き、Unicodeコードポイント数1〜80文字とする。APIはNULを拒否する。名前をHTMLとして解釈しない。
- `PATCH /api/v1/me/profile` は本文 `{display_name}` のみ、200 `{data:{id,display_name}}` を返す。未認証401、Origin不一致403、不正入力400、JSON以外415、32KiB超413。応答は `private, no-store`。
- RPC `public.update_my_profile(p_display_name text)` は本人の `auth.uid()` のみ更新する。対象IDを受け取らず、DBでも空白除去・長さを検証する。`project_hub_owner` 所有・空のsearch_path・authenticatedのみEXECUTE、profilesへの直接更新は引き続き拒否する。新規migration011で追加する。
- 保存中は二重送信を防ぐ。エラー時は入力を残し再試行できる。成功メッセージを表示し、ログイン状況を最新化する。360pxとキーボードで操作できる。
- メンバー一覧・担当者候補は再取得時に新しい表示名を返す。既存の操作履歴の `actor_display_name` とコメントの投稿者名はスナップショットのまま保持する。
- 初期名「デモメンバー」は維持する。メールアドレスのローカル部を自動公開することを避け、本人の明示操作で変更する。

## 検証

DBテストで本人更新、他人のID指定・直接更新・匿名呼出の拒否、空白・80/81コードポイント境界、無所属での操作、過去の履歴名の保持を確認する。認証E2EでAPI入力・Origin・形式・サイズ・認証検証、360pxの保存・メンバー一覧への反映と通信失敗からの再試行を確認する。統合時にlint・typecheck・build・DB・認証E2Eを実施する。
