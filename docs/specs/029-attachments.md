# タスク・課題の添付ファイル

Issue: [#81](https://github.com/kiyohara1021/project-hub/issues/81)

## 目的・範囲

タスク・課題に資料を添付し、閲覧権限のある利用者だけがダウンロードできるようにする。公開URL、ファイルのインライン表示、画像編集、マルウェア検査サービスは対象外。

## 契約

- Supabase Storageの非公開バケット`project-attachments`を使う。通常アプリはユーザーJWTだけで操作し、管理鍵を持たない。保存先はサーバーで発行したUUIDとし、元のファイル名をパスに使用しない。
- 各タスク・課題は予約中も含め最大20件。ファイルは1〜3MiB、multipart全体は4MiBまで。PNG・JPEG・WebP・PDF・UTF-8テキストを許可し、拡張子とMIMEと内容の先頭識別子をサーバーで照合する。テキストは全体のUTF-8と制御文字を検査する。完全な形式解析やウイルス検査の保証とは扱わない。
- 投稿は有効なプロジェクトのadmin/member、閲覧は現在の親とプロジェクトを閲覧できる利用者に限る。非公開設定と参加解除はStorageとアプリ双方で反映する。削除は投稿者本人またはworkspace adminに限り、アーカイブでは閲覧のみ。
- アプリのダウンロードAPIは認可後にサイズ・MIME・内容識別子・SHA-256を再確認し、`Content-Disposition: attachment`・`X-Content-Type-Options: nosniff`・private/no-storeで返す。3MiB以内を検証してからレスポンスをstreamする。ファイル名はヘッダー用に符号化する。
- メタデータ予約→Storage保存→公開確定の順で行う。予約は1時間で失効する。失効だけでは添付枠を解放せず、保守回収後に空ける。同じ再送キー・同じファイルの再試行は同じ予約を使い、保存後に応答が失われた場合も重複しない。
- メタデータと物理オブジェクトの回収台帳を分離する。親の削除はメタデータをCASCADE削除し、台帳へ削除待ちを残す。通常の削除も先に公開を止め、Storage APIで消去し、失敗時は台帳を残す。`storage.objects`をSQLで直接削除しない。
- 期限切れ予約・親削除・失敗した消去は管理用CLI認証の保守スクリプトで回収する。既定は対象表示だけで、`--execute`時だけStorage APIを実行する。月次と削除失敗時に対象を確認・回収する。通常アプリへ管理鍵を追加しない。
- 添付の公開・削除を操作履歴へ残す。ファイル名・本文・保存パス・内容のハッシュは操作履歴へ記録しない。
- 作成前のタスク・課題には添付しない。保存後に編集から開ける。閲覧者とアーカイブでも独立した「添付ファイル」ダイアログから一覧・ダウンロードを利用できる。

## 受け入れ条件

- DBテストで予約数、期限、再送、親とworkspaceの整合、権限、アーカイブ、親削除時の回収台帳を検証する。
- 認証E2Eでupload/list/download/delete、MIME・内容・容量の拒否、viewer/別workspace拒否、Storageの直接アクセス拒否、360pxの操作を確認する。
- 親削除とStorage削除失敗が公開済みの孤立ファイルを残さず、保守用の一覧と回収を実行できる。
