# 一覧APIのローカル負荷検証

## 目的・範囲

基本設計の「架空100プロジェクト・1,000タスクで一覧API p95 1秒以内」を再現可能なローカル検証にする。本番への負荷試験は行わない。小さな本番サンプルの既存ブラウザ計測とは別の結果として記録する。

## 受け入れ条件

- `pnpm test:load` でビルド済みNext.jsを127.0.0.1:3104に起動し、Supabase CLIで検証済みの127.0.0.1:54321だけを利用する。接続先や資格情報を引数・ログに出さない。既存サーバーを再利用しない。
- 毎回専用workspaceを作り、架空100プロジェクト・合計1,000タスクを生成する。1プロジェクトに901件、残る99プロジェクトに1件ずつ。全タスクはtodo。生成はローカル管理クライアントだけで行い、計測はログインで得た通常ユーザーCookieからNext APIに送る。
- プロジェクト一覧と高密度プロジェクトのタスク一覧を各limit=25/100で測定する。各条件5回のウォームアップ後50回を順次送信する。同時接続数は1で、自動再試行しない。応答本文の受信・JSON解析までを含む。
- 毎回HTTP200、件数、ページ上限、nextCursorを検証し、失敗応答を成功時の分位点へ混入させない。失敗は試験失敗にする。
- 条件別に件数・min/p50/p95/max・p95目標達成を出力する。分位点はnearest-rank。全条件p95が1,000ms以内なら成功、未達は非ゼロ終了で記録する。
- 成功・例外・SIGINT/SIGTERMでも可能な限り子サーバー停止と専用workspaceの全fixtureを削除する。既存workspace・ユーザー・共有seed・マイグレーションは変更しない。Cookie・トークン・鍵・本文を出力しない。
- 計測した日付・Node/PostgreSQL・対象SHA・件数・サンプル数・条件・集計結果と限界を資料へ記録する。

## 限界・対象外

ローカルの単一プロセス・同時実行1・ウォーム状態での回帰確認であり、本番ネットワーク、Vercel/Supabase無料枠、コールドスタート、複数ユーザー高負荷の性能保証ではない。課題・メンバー・操作履歴・ダッシュボードはこの目標の測定対象に含めない。アプリの認可やDB定義を変更しない。

## 実装・検証記録（2026-11-03、Issue #34）

`pnpm test:load`を実装。lint/typecheck/build成功。全4条件で50回ずつ成功し、p95は11.17〜18.67ms。fixture削除後の残存0件を確認。ポート衝突拒否とworkspace作成後のSIGTERM cleanupも別途確認済み。[詳細な条件・結果・制約](../performance.md#100プロジェクト1000タスクのローカル一覧api検証)を参照。
