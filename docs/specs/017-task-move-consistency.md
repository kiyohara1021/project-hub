# タスク移動時の並び順と編集競合（Issue #43）

## 仕様

移動先の前後のタスクのpositionの中間整数を使い、先頭・末尾では1024の間隔を使う。整数の隙間やbigintの範囲が足りない場合だけ、移動先を1024刻みで振り直す。workspace、projectの既存ロック順に従って直列化する。

移動対象のversionとupdated_atだけを更新する。位置の内部調整では他のタスクのversion、updated_at、内容を変更せず、取得済みversionでの編集を引き続き受け付ける。履歴トリガーはtasksのpositionだけが変わった更新を除外し、1回の移動につき移動対象のUPDATEを1件記録する。一般の編集、ステータス変更、作成・削除の監査は従来通り。

既存migration003を変更せずmigration010で関数を置換する。RPC入力・認可・アーカイブ制限・楽観ロックの契約は維持する。

## 検証

DBテストで通常の中間挿入、整数間隔が尽きた振り直し、他タスクのversionとupdated_at維持、元versionでの編集、両ケースの履歴1件を確認する。
