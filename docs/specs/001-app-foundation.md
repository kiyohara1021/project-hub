# P1: アプリケーション基盤

> 実装時の仕様（対応済み）です。「対象外」はこの段階の作業範囲を示します。現在の動作は[基本仕様](../specification.md)、追加・変更の関係は[仕様一覧](README.md)を参照してください。

関連: [Issue #1](https://github.com/kiyohara1021/project-hub/issues/1)

## 目的

設計済み6画面の構成を、起動可能なアプリで確認する。今回のデータはすべて固定のサンプルデータ。認証・DB・CRUDの実装を完了したと誤認させない。

## 受け入れ条件

- AC1: `/` は `/dashboard` へ遷移し、6画面にナビゲーションから到達できる。
- AC2: プロジェクト一覧で名前検索ができ、0件時には空状態を表示する。
- AC3: 選択したプロジェクトのIDをカンバン・課題のURLに保持し、不正IDは404とする。デモB/Cは空状態を表示する。
- AC4: 360px幅で本文の横方向スクロールが発生せず、メニューとカンバンの状態選択を操作できる。
- AC5: メニューはキーボードで開閉できる。本文へのスキップリンク、入力ラベル、見出しを備える。
- AC6: 共通の読込、失敗、404状態を用意する。認証・保存未接続を全画面で明示する。
- AC7: クリーンインストール、lint、型チェック、ビルド、主要画面のE2Eが成功し、PRにCIを設定する。

## 実装計画

Next.js App Router / TypeScript / Tailwind / shadcn/ui。ページはServer Componentsを基本にし、ナビゲーション、検索、状態タブだけをClient Componentsにする。外部フォントや外部APIに依存しない。lockfileをコミットする。

## 意図的な差分・対象外

SVGは将来の完成画面案。P1では操作しないボタンを置かず、データ作成・編集・ドラッグはP2以降に実装する。検索は固定データに即時適用し、API検索時の300ms待機とURLへの条件保持はP3で追加する。カンバン/課題のサイドバーはP1ではデモAへのショートカットで、プロジェクト間の移動は一覧から行う。ダッシュボード数値は固定例であり、タスク一覧から算出していない。

## 検証

PlaywrightでAC1〜4の主要操作と不正ID、キーボードメニューを確認。lint/型/ビルドで整合性を確認。ローディングと障害時の共通境界はコードレビュー対象とし、DB障害の結合テストはP2以降。
