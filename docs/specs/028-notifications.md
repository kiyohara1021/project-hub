# アプリ内通知

Issue #80。担当になった作業と参加中の課題の新しいコメントを、本人だけが確認できる通知一覧へまとめる。メール・ブラウザPush・期限の自動通知・通知設定・本文の抜粋は対象外。

## 通知の発生

- タスク・課題の作成時または担当者変更時に、新しい担当者へ通知する。担当なし・担当者が変わらない更新・自分自身への割当は通知しない。
- 課題への新しいコメントは、課題の現在の担当者と、その課題へ過去にコメントした利用者へ通知する。投稿者本人を除外し、担当者と投稿者の重複は1件にまとめる。コメントの編集・削除では通知しない。
- 通知の作成は元データの更新と同じDBトランザクションで行う。再送によって元のINSERTが再実行されない場合は通知も増やさない。さらに受信者・種別・発生元ID・versionで一意にする。
- 通知先は発生時点で対象プロジェクトを閲覧できる利用者に限る。ユーザーの操作による変更を対象とし、auth.uid()のない管理・seed処理から通知は作らない。

## 保存と権限

migration017で`public.user_notifications`を追加する。通知ID、受信者、workspace/project、対象種別/ID、通知種別、発生元ID/version、任意のコメントID、作成日時、既読日時を保存する。作業のタイトル・説明・コメント本文・操作者の名前はコピーしない。

通常ユーザーは直接SELECTのみ。RLSは受信者本人、現在のプロジェクト閲覧権限、対象タスク/課題の現存、作成後90日以内を全て要求する。他人の通知、所属解除後、非公開プロジェクトの許可解除後、対象削除後は一覧と未読件数の両方から消える。コメント削除時はそのコメント通知を連鎖削除する。通常ユーザーが通知を作成・書き換え・削除する経路は設けない。

既読は本人用RPCだけで変更する。既読済みの再実行は成功し、最初の既読日時を維持する。個別操作で他人・閲覧不可・存在しない通知IDは同じ404とする。一括既読は現在閲覧できる本人の未読通知を対象とし、別の利用者や後から発生した通知を変更しない。関数はproject_hub_owner所有、空のsearch_pathとし、利用者向けRPCだけauthenticatedへEXECUTEを許可する。

## APIと画面

- `GET /api/v1/me/notifications`：`limit`（既定25、最大100）・`cursor`・`unread=1`だけを受け付ける。created_at DESC/id DESCのkeysetページ送りで`{data,nextCursor,unreadCount}`を返す。
- `GET /api/v1/me/notifications/unread-count`：現在参照可能な通知の`{unreadCount}`を返す。
- `POST /api/v1/me/notifications/:id/read`・`POST /api/v1/me/notifications/read-all`：JSON空オブジェクトを受け付け、個別は`{data:{id}}`、一括は`{data:{updated}}`を返す。
- 認証なし401、Origin不一致403、不正なID/クエリ/本文400、形式違い415、32KiB超413。全応答private/no-store。DBの内部情報をエラーへ表示しない。
- `/notifications`に未読件数、全件/未読の切替、通知種別と日本時間の日時、対象へのリンク、個別/一括の既読ボタンと次ページを表示する。本文や名前を含めないため、受信時の古い内容を表示しない。
- 保存中の二重送信を防止し、失敗時は一覧を残して再試行を案内する。ページ取得失敗にも再試行画面を用意する。PC・360px・キーボードを確認する。
- `NotificationLink`はヘッダーに通知リンクと未読件数を表示する。初回、画面遷移、再フォーカス、既読操作後に再取得し、自動ポーリングは行わない。取得失敗時は件数を隠してリンクを維持する。Previewでは通知の空表示を用意し、DBへ接続しない。

## 保持と定期削除

通知は90日保持し、管理者用`private.purge_old_notifications(p_limit default 1000)`で古い行を最大1,000件ずつ削除する。許容上限は1〜10,000件、並行実行をadvisory lockで抑止し、ロック済み行を待たない。通常の利用者・service_roleに実行を許可しない。元データと操作履歴は削除しない。

pg_cronが利用可能なら`project-hub-notifications`を`27 3 * * *`に登録し、30秒のstatement_timeout・1秒のlock_timeoutで実行する。同じジョブが生成した実行履歴の完了後7日超も1回最大10,000件まで整理する。他ジョブの履歴は触らない。拡張がない環境ではNOTICEを出し、関数だけ導入する。時刻はcronのtimezoneに従い、本番でジョブ登録と実行成功を確認してから定期削除済みと扱う。

## 検証

DBテストで担当割当/変更、自分への通知なし、コメントの受信者集合と重複/再送、本文を保存しないこと、RLS・直接更新拒否・既読の本人境界、ACL/所属解除・対象削除、90日境界とbounded purgeを確認する。認証E2Eで入力と認証/Origin、一覧/未読/同時刻ページ送り、既読・失敗復旧・360pxを確認する。全体の整形・lint・型・ビルド・DB/認証E2Eは統合時に実行する。
