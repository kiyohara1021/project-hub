# P3-2: DB接続ダッシュボード

関連: [Issue #9](https://github.com/kiyohara1021/project-hub/issues/9)

## 受け入れ条件

- AC1: connectedモードはログイン必須。所属workspaceを選択してURLに保持し、無所属は空表示、別workspaceと不存在は同じ404。previewモードの固定表示は維持する。
- AC2: アーカイブを除くplanned/activeプロジェクトを集計対象とする。「進行中」はactive件数、完了率は全対象タスクのdone数÷総数を四捨五入した整数（0件は0%）、期限超過は未完了かつdue_dateが日本時間の今日より前。未解決課題はopen/investigatingのみ。
- AC3: プロジェクト進捗は新しい順で最大5件、自分の未完了タスクは期限が近い順（未設定は末尾）で最大5件、最近の操作は対象workspace全体（アーカイブ含む）から最新5件。並び順の末尾にidを加えて安定させる。
- AC4: 集計はRLS付きのSECURITY INVOKER関数を使い、単一スナップショットで全件を数える。APIの1000行制限で集計を切り捨てず、admin/member/viewerとも所属外の数値・名前を返さない。個人タスクはauth.uid()のみから特定する。
- AC5: GET `/api/v1/workspaces/:wid/dashboard` は検証済みJWTで読取。任意の集計日やユーザーIDを受け取らない。不正UUID/クエリーは400、未認証401、所属外404、失敗は詳細を隠した500。API/pageとも共有キャッシュを使わない。
- AC6: 空プロジェクト/タスク/履歴を明示し、0件でも固定値に戻さない。エラーは再試行可能。360pxで横にはみ出さず、自分のタスクからカンバンの該当状態・担当者へ移動できる。
- AC7: DBでJST日付境界、1000行超、未完了/今日/期限なし/完了、未解決課題、アーカイブ、0件、所属分離を検証。API/画面で認証・URL・更新反映・モバイル・障害復旧を確認しCI成功。

## 判断と対象外

全体完了率はプロジェクト別パーセンテージの平均ではなく、タスク数で重み付けされた割合。課題はDBの架空seedも集計するが、課題管理画面自体のDB化は次段階。最近の操作は本文・変更ペイロードを返さず、操作種別・架空表示名・日時だけを表示する。自動ポーリング、リアルタイム同期、クラウド、デプロイは対象外。更新を反映するには「最新の状況を取得」または再読込を使う。

カンバンには任意の表示列を指定する `column=todo|doing|review|done` を追加し、モバイルの初期表示に使う。担当者とworkspaceもリンクに保持する。
