# 自分のプロフィールの編集

Issue: [#76](https://github.com/kiyohara1021/project-hub/issues/76)

[表示名変更の仕様018](018-profile-display-name.md)を拡張し、任意の役職・担当と自己紹介を本人が設定できるようにする。メールアドレス・パスワード・アバターの変更はこの仕様の対象外とする。

## 項目と公開範囲

- `display_name`は既存どおり、前後の空白を除いて1〜80文字。
- `job_title`（役職・担当）は0〜80文字、`bio`（自己紹介）は0〜500文字。いずれも任意で、空文字で削除できる。
- 文字数はUnicodeコードポイント数で数え、JavaScriptの`trim`と同じ前後の空白を除く。NULを拒否する。自己紹介の途中の改行は保持し、本文をHTMLとして解釈しない。
- 新しい項目は既存の`profiles`の閲覧権限に従う。本人および同じワークスペースに所属する利用者が参照できる。全体公開するプロフィールは作らない。
- `profiles`の既存レコード・新規レコードの追加項目は空文字を既定値とする。本人のIDは認証情報から確定し、対象ユーザーIDは受け付けない。所属先がない利用者も編集できる。

## APIとDB

- `PATCH /api/v1/me/profile`は必須の`display_name`と、任意の`job_title`・`bio`を受け付ける。他のキー、null、型違い、長さ超過、NULを拒否する。省略した追加項目は既存値を保持する。
- `display_name`のみの既存リクエストは、応答`{data:{id,display_name}}`を維持する。追加項目を1つ以上指定した場合は`{data:{id,display_name,job_title,bio}}`を返す。認証・Origin・32KiB上限・JSON形式・private/no-storeは仕様018を維持する。
- migration014で列と長さ制約を追加し、`public.update_my_profile_details(p_display_name text,p_job_title text default null,p_bio text default null)`を追加する。認証した本人の3項目を単一UPDATEで保存する。追加項目のnullはRPC内部では「変更しない」を表す。既存の`update_my_profile(text)`は維持し、追加項目を変更しない。
- RPCは`project_hub_owner`所有、SECURITY DEFINER、空のsearch_path、authenticatedのみEXECUTEとし、通常ユーザーの直接更新権限を追加しない。
- プロフィールは従来と同じく最後に保存した内容を採用する。追加のversion契約は導入しない。既存の操作履歴・コメントの表示名は変更せず、役職・自己紹介の本文を履歴へ記録しない。

## 画面

ログイン状況の「プロフィールの変更」フォームに表示名・役職・担当・自己紹介を表示する。「プロフィールを保存」でまとめて保存し、成功後に表示値を正規化する。保存中の再送を抑止し、失敗時は入力を残して再試行を案内する。入力内容を破棄する自動再取得は行わない。PC・360px・キーボードで操作できる。

## 受け入れ条件・検証

- DBテストで80/81・500/501コードポイント境界、前後空白・途中改行・空文字での削除、省略時保持、無所属での保存、匿名/他人ID/直接更新の拒否を確認する。
- 認証E2Eで追加キーと型・NUL・長さ検証、旧リクエストの互換性、部分更新時保持、360pxでの保存と再表示、通信失敗後の入力保持を確認する。
- 既存の表示名反映と過去の履歴保持のテストを維持する。変更全体で整形・lint・型・ビルド・DB・認証E2Eを確認する。
